# What Is a Code Editor?

## The Simple Version

A code editor is a program for writing code. It's like a text editor (Notepad, TextEdit) but with superpowers designed for programming:

- **Syntax highlighting** — colors different parts of your code so it's easier to read
- **Auto-completion** — suggests what you might type next
- **Error detection** — underlines mistakes before you even run the code
- **File explorer** — shows all the files in your project in a sidebar
- **Built-in terminal** — run commands without leaving the editor

You *could* write code in Notepad. But a code editor makes it 10x more productive and less error-prone.

## How It Relates to Your Setup

### If you're using the sandbox path

The sandbox can include **VS Code Server** — a version of VS Code that runs in your web browser. No installation needed on your computer. You access it by opening a browser tab.

### If you're using the direct install path

Your AI coding assistant (OpenCode) runs in the terminal, not in a code editor. You don't *need* a separate editor — OpenCode creates and edits files for you. But if you want to browse and read your code, having VS Code installed is nice:

1. Download from https://code.visualstudio.com
2. Install it
3. Open it, then **File > Open Folder** and select your project folder
4. You can see all your files, read the code, and even use the built-in terminal (View > Terminal)

## Code Editor vs. AI Coding Assistant

These are different things that work well together:

- A **code editor** is where you view and manually edit files
- An **AI coding assistant** (OpenCode, Claude Code, etc.) writes and modifies code for you based on what you describe

Some tools combine both — **Cursor** is a code editor with a built-in AI assistant. **GitHub Copilot** is an AI assistant that plugs into VS Code.

## Do You Need a Code Editor to Get Started?

**No.** Your AI coding assistant handles file creation and editing. But having a code editor open alongside it lets you:

- See your project structure at a glance
- Read the code the AI wrote
- Make quick manual edits when it's faster than describing a change
- Learn by browsing real code

Most people start by letting the AI do everything, then gradually open a code editor to understand what's happening. There's no rush.
